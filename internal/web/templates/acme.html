RFC 8555, External Account Binding only — no HTTP-01/DNS-01 challenge is ever validated. An EAB credential is the trust decision: it binds every account bootstrapped with it to one authority, one profile, and optionally a set of domains.

New EAB credential

Identifies this credential in lists and audit entries — e.g. the cluster or team it's issued to.

Comma separated shell-glob patterns. * matches across dot boundaries, so *.internal.lab also covers a.b.internal.lab. Leave blank to allow any domain — the authority itself may still be constrained separately.

0 = unlimited. Most setups need exactly 1 (one cert-manager Issuer).

0 = never. Only disables new registrations — existing accounts keep working.

The same thing from the CLI

goca acme eab create cluster-a \
  --ca acme-issuing-ca \
  --allowed-domain '*.svc.cluster-a.internal' \
  --max-accounts 1

goca acme eab list
goca acme eab show cluster-a
goca acme eab disable cluster-a
goca acme accounts list

Disabling a credential stops it bootstrapping new accounts; accounts already created with it keep renewing, since from registration onward they sign with their own key, not the EAB secret.
