Subject for the new subordinate CA

The validity of the resulting CA is decided by the signing authority, not here.

On pfSense: System → Cert. Manager → CAs → Add, choose Sign an intermediate Certificate Authority, paste the request goca gives you, pick the signing CA, then export the issued certificate and import it back here.

The CA certificate

Or paste it below. If the file holds several certificates, the first is the authority and the rest are treated as its chain.

Its private key

Verified against the certificate, then encrypted with the server master key. Encrypted keys must be decrypted first: openssl pkcs8 -topk8 -nocrypt -in enc.key -out plain.key

Issuer chain (optional)

The issuers above this certificate. Anything not already stored is imported as a trust anchor, so chains resolve to a root.

The same thing from the CLI

# 1. generate the request here, key stays on this server
goca ca request --name "Branch Issuing CA" --common-name "Branch Issuing CA" --out branch.csr

# 2. sign branch.csr on pfSense, then bring the result back
goca ca import-signed branch-issuing-ca --cert signed.crt --chain pfsense-root.crt

# or, if you already have the intermediate and its key
goca ca import --cert intermediate.crt --key intermediate.key --chain root.crt --default

# or just the root, so chains resolve
goca ca import --cert root.crt --name "pfSense Root CA"
